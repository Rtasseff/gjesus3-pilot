1 · Executive summary

What it is, where it stands, what we need from you

The problem

NI researchers run the Molecubes scanner themselves. Getting data out has meant staying in the acquisition room and copying reconstructions by hand to the gnuclear working space. There the same reconstruction ends up in many folders (up to 48 copies of one scan), filed by personal habit. None of it is registered, checksummed or tied to its animals and project. When the August backfill pulled that space into gjesus3, it found 2,312 acquisitions, and 673 of them still cannot be filed because no protocol code was recorded.

The solution

A sync the researcher runs at the Mac when reconstructions finish. It is two commands: --plan shows what's new, then a second run syncs it. Each reconstruction is copied to gjesus3 raw/, checksummed, described in a metadata sidecar, registered and filed in its project. The researcher's folder on the box is only ever read. Mistyped folder names and the tracer are fixed once, in a small per-researcher corrections file.

Where we are

  • Proven in production on 8 Oct. Irene's whole box folder: 95/95 reconstructions (6.07 GB, 25 min, Mac load ≤1.7). Every check passes: checksums 95/95, registry validator 0 errors, 95 project links as true hard links, and 145 animal records matching the animal-facility DB.
  • Access solved. Since 1 Oct the Mac is operable from the Data Office through a hardened reverse SSH tunnel. Unai (NI platform manager) approved remote sync tests on 2 Oct.
  • Two serious defects caught before they reached researchers, both fixed and tested: re-ingesting scans another route had already loaded (75 would have been duplicated), and a recovery tool writing one mouse's record into another's block (25 sidecars, repaired and verified the same night).
  • Ready for researchers: a production copy on gnuclear, an ni-ingest shortcut on the Mac, and an illustrated guide. 47 automated test suites pass, and the branch merges cleanly into main.

Next two weeks

3 · What we built

The sync, end to end

Design principles

  • The box is read-only. The sync never moves, renames or deletes anything in a researcher's folder.
  • One acquisition per reconstruction. A reconstruction that finishes weeks later becomes its own entry and inherits the session's corrections.
  • Fix once. A per-researcher corrections file holds typo fixes and the tracer, permanently.
  • Nothing twice. Scans loaded by another route are recognised by timestamp, modality and reconstruction number.
  • Derived is not raw. CT attenuation maps go to the project as derived files, traceable to their scan.

Rules that shaped it

  • The platform's box, the platform's terms. Small CPU and I/O footprint, nothing written outside one Data Office folder, nothing deleted. Unai's concern is code nobody can read and anything that erases.
  • Demonstrable, not just readable: --plan and --dry-run show every path read and written, and touch nothing.
  • Project names (your rule, 8 Oct): 4 digits in the code position = AE-biomaGUNE-NNNN; anything else = Project-<code>. No DB check on the Mac; the later animal lookup surfaces bad codes.
  • No questions mid-sync: one batch-wide answer can't be right for many studies.

5 · Access to the box

The reverse tunnel, and the rules for using it

The Molecubes Mac sits on the scanner's private network, so nobody could reach it from outside. Every test before October needed a person in the acquisition room, and access was lost for a month.

Security posture

The Mac's tunnel key is restricted to port-forwarding; it cannot run commands on the workstation. The Data Office's login key to the Mac is recorded, and removable in one step.

Your rules for the Mac

Write freely only in your gnuclear folder. Every other write needs your OK. Never delete what we didn't write. Keep reads small and runs at low priority, outside acquisitions.

Known limits

After a Mac reboot the tunnel returns only when someone logs in (no auto-login). The gjesus3 mount uses your login for now (section 8); MacMounter re-mounts it automatically within 2 minutes.

Box A, the planned server, takes over the tunnel without a site visit. The move is decided and planned make-before-break: a second connection is proven before the first is removed. Once Box A pulls data through the tunnel, the Mac needs no gjesus3 mount and no stored credentials.
