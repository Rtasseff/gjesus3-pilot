# Per-user access logging on gjesus3: feasibility study
*2026-10-05, for Ryan Tasseff (Data Office). Feasibility only: nothing was built, changed, switched on or probed, and I did not contact the NAS.*
Tags: **[D]** verified in published documentation · **[R]** verified in this repo · **[I]** my inference; needs a test or confirmation.

## Answer in one paragraph
Yes for the NAS, not yet for the two apps. QNAP's built-in log tool (QuLog Center) can record, per Windows user, which files were opened, read, written, deleted or renamed on the SMB share (the Windows file-sharing protocol), with user name, PC address, PC name, path and time [D]. It costs a switch in the NAS admin console, a log volume the NAS must carry (QNAP warns of a "slight" slowdown), a retention rule and, before anything is switched on, a data-protection process with the DPO and notice to staff and their representatives. It cannot be limited to one folder, so the Data Office's own batch jobs would fill part of it [D/I]. Per the repo the likely switch-holder is institute IT; nothing shows the Data Office has QNAP admin-console rights [R]. Neither app is a web server: the Finder is a file opened over SMB (nothing inside the page is visible to anyone) and the Project Manager is a program on each user's own PC, so there is no central web log to read [R]. The Project Manager already writes a provenance row per import, but with a typed name, a date without time, and nothing for project edits [R]; a small audit log stamped with the Windows username is about a day's work for the Data Office [I]. The planned server-era web app will know the logged-in user for free [R] and is the cheaper place to build per-user logging [I].

## 1. The NAS, `\\GJESUS3\gjesus3`
- **Switch-on and viewing [D].** QuLog Center > Local Device > Log Settings > Access Log Settings: pick a log destination, maximum entries and retention time, tick Connection Types (it includes "SMB (Windows)"), Apply. Read it under Local Device > Access Log (group by user or source IP; search a file name in "Accessed Resources"). "Online Users" is a live list of who is connected now (user, IP, connection type, login time).
- **What is recorded [D].** User, source IP, PC name, connection type, path, action (QNAP FAQ; a third-party sample Samba event).
  - QNAP's 4.x manual lists delete, read, write, open, make-folder, rename, copy, move, add, login ok/fail, logout. The 5.x pages only say "detailed record of user access to applications and files", so confirm the event list on the device [I].
  - Folder browsing is not in the list and file contents are never logged [I]. Share permissions use the domain group `CICBIOMAGUNE\GJesus` (`mfb-rdm-docs\11_OPERATIONS.md:72`) [R], so names probably read `DOMAIN\user` [I].
- **Performance and QNAP's warnings.** "File transfer performance may be slightly impacted when this feature is enabled" (4.x manual) [D]; the 5.x access-log pages carry no performance note [D]. QNAP separately warns that high-level Samba *debug* logging "may affect NAS performance" and can fill the system partition, so it is no audit trail [D]. The NAS is a Celeron N5095 with 8 GB [R]: size it with a short trial [I].
- **Capacity and retention [D].** Up to 5,000,000 access entries stored, 100,000 shown at a time, 10,000 per export file (CSV or HTML). Two limits apply, maximum entries and retention time; the oldest entries are deleted or moved. The cap counts entries, not days: a full checksum pass over about 344,000 linked files (`tasks\BACKLOG.md:1672`) or an ingest could use a large share in one run, if each file open is one entry [I].
- **Archive and forwarding [D].** Log Sender (QuLog Service) sends event and access logs to a syslog server (port 514 typical) or to another QNAP's QuLog Center; Log Receiver (up to 500 devices, own retention) can make a second NAS the archive. Overflow archiving to a standby folder is documented for event logs; check the access-log screen. "Delete all access logs" cannot be undone, so only a forwarded copy protects the record [D/I].
- **Preconditions [D].** Logs go only to an unencrypted local volume with at least 10% free space (a community user on an encrypted volume was refused). Ask IT whether the volume is encrypted and whether SMB logging is already on; defaults are not documented.
- **Samba `full_audit` [D].** Not exposed: QNAP's Microsoft Networking page has no logging, audit or custom-parameter setting, and `smb.conf` is regenerated by QNAP's script (community: edits do not persist). Unsupported; I would not rely on it [I].
- **Admin rights [D].** A QNAP administrator, or the delegated "System Management" role, which is broad (it also covers Control Panel and Storage & Snapshots).
- **Firmware, and how to check without logging in [D].** The repo records only "QTS 5.x (or QuTS hero)", file system unconfirmed (`mfb-rdm-docs\02_INFRASTRUCTURE.md:41,53`); QNAP lists the TS-864eU with QTS 5.2.9 (ext4) or QuTS hero h6.0.0 (ZFS). Qfinder Pro (free; Windows, macOS, Ubuntu) lists each NAS on the LAN with its "Firmware Version", no login needed.
  - Version-dependent: the event list (documented for 4.x, not restated for 5.x); from 5.1.7, repeated SMB login failures within 3 seconds merge into one entry; the faster "kernel-mode SMB daemon" option exists on x86 models [D], this one included (Intel CPU, `02_INFRASTRUCTURE.md:24`) [R], and I found no statement on whether file-level logging still works with it [I].
- **Fit with gjesus3 [R/I].**
  - Instrument and platform PCs run shared logins (`mfb-rdm-docs\11_OPERATIONS.md:30`; `09_MODALITIES.md:115`), so those entries name a login and a PC, not a person.
  - A file opened through `raw_linked\` probably logs the project link name, not the ACQ-ID, so tracing back needs the registry [I]. Both apps run under the user's own account, so their file writes would be attributed to that person; whether hard-link creation is logged is unknown [I].
  - The strongest reason to log is the human-subject data (DTS24, LEONE; `tasks\BACKLOG.md:18-25,773-799`), and it cannot be isolated from the rest of the share.

## 2. The Finder (static HTML opened over SMB)
- **Today [R].** `registries\index.html` and each project's `index.html` are self-contained: the data is embedded and the only thing the page does outside itself is copy a path to the clipboard (`tools\generate_index.py:20-22,201-202`; `tools\FINDER.md:10-14`). There is no server.
- **What the NAS sees [I].** With SMB logging on: one connection by that user's PC and an open and read of that one large file. Searching, filtering and "Copy path" create no traffic, so they are invisible; a locally copied file is invisible too. The useful trace is the next step: opening `raw\...` or `projects\...` in Explorer appears as file events under the same user. The 03:00 daily rebuild appears as writes by Ryan's account (`mfb-rdm-docs\11_OPERATIONS.md:368`) [R].
- **If served over HTTP [D/I].** A web server logs time, client address, page and size. A user name appears only when sign-in is required: Microsoft's web server (IIS) writes the authenticated user to its log, and Windows sign-in needs a domain-joined Windows host (Box A would be one: `tasks\box_a_production_migration_plan.md:50`) with the site trusted as "intranet" in the browser; IT may be needed for the host name or certificate.
  - In-page searches stay invisible unless the Finder becomes a dynamic app where each search is a request (`tasks\BACKLOG.md:2826-2833`); the search text is then personal data to minimise. The Finder would also depend on a server being up.
  - The no-admin WSL port-forward (a Data Office note outside the repo) matters only here: a plain forwarder hides each visitor's address from the web server's log and cannot do Windows sign-in [I]. A real server on Box A avoids both.

## 3. The Project Manager (and the ingest GUI)
- **What it is [R].** A local Flask program frozen as `gjesus3_manager.exe`, started by each researcher from `\\GJESUS3\gjesus3\gjesus3-data\tools\` on their own PC. It listens only on that PC (`127.0.0.1`, port 5001) and talks to that user's own browser, with a console window (`mfb-rdm-docs\10_TOOLS.md:1164-1224`; `tools\manager\gui\app.py:561-574`; `tools\manager\gui\gjesus3_manager.spec:126`). `gjesus3_ingest.exe` (port 5000) is the same pattern (`tools\INDEX.md:74`).
- **Already recorded [R].**
  - Per import, one `provenance.csv` row in the project: `creator` is a name typed in a required box (`app.py:414-417,479-482`), the date is UTC with no time (`tools\manager\raw_import.py:306`), plus what was done and the tool version (`tools\ingest\provenance.py:22-35`).
  - Project edits overwrite `registry_projects.csv` in place with no who or when (`tools\manager\projects.py:75-139`); `owner` is free text (`tasks\BACKLOG.md:2188-2195`).
  - `registry_raw.csv` holds the declared `researcher` and `operator` plus `ingest_config`, not who pressed the button (`tools\ingest\registry.py:18-70`). The import log is streamed to the browser and not saved (`app.py:515-547`).
  - Provenance rows sit in researcher-owned folders that may be edited or deleted, so they are no audit trail (`mfb-rdm-docs\05_PROJECTS.md:201-212`).
- **A small audit log, cost [I].** One helper (about 50 lines) called by the write actions (create, edit, import from raw, import local, app start), appending UTC time, `DOMAIN\user`, PC name, action, project, counts and result; no file names or search text.
  - Identity from `getpass.getuser()`, which reads environment variables: fine for a cooperative trail, not proof [D]; Data Office tools already use it (`tools\retire_acquisition.py:1716`) [R]. Weak on shared logins (`tasks\BACKLOG.md:2185-2186`).
  - A central file that every researcher can append to is one they can also edit; the create-but-not-modify permission pattern (one new file per event) would protect it, but that pattern is still unverified over SMB (`mfb-rdm-docs\11_OPERATIONS.md:84,109`) [R].
  - About 1 day with tests and the exe rebuild-and-redeploy routine (`CHANGELOG.md:47`); the same helper would cover the ingest GUI.
- **Better moment [R].** `tasks\BACKLOG.md:2177-2206` plans a server-era web app where the logged-in user fills `owner`, `creator` and edit rights, and Box A is to host a single ingest web app (`tasks\box_a_production_migration_plan.md:213`). Logging built there needs no retrofit of the exes.

## 4. Privacy and legal cost (obligations named, not legal advice)
- **GDPR [D].** A lawful basis (Art. 6; "legitimate interests" needs a balancing test); a specific purpose, minimisation, storage limitation, accountability (Art. 5(1)(b),(c),(e), 5(2)); information to staff when collecting, including the retention period (Art. 13(1)(c), 13(2)(a)); an entry in the record of processing with erasure time limits (Art. 30(1)(f)); an impact assessment if the risk is high, with the DPO's advice (Art. 35(1),(2)); collective agreements may add rules on workplace monitoring (Art. 88(2)).
- **Spain [D].** LOPDGDD art. 87: privacy in work digital devices; the employer sets the use criteria with the participation of workers' representatives and must inform workers. Art. 91: collective agreements may add guarantees (check the institute's). Arts. 88-90 (disconnection, video and sound, geolocation) do not fit NAS logs [I].
  - Estatuto de los Trabajadores art. 20.3 (employer control, respecting dignity) and art. 64.5(f) (the works council may report before "sistemas de organización y control del trabajo" are introduced).
  - AEPD guide (Dec 2025, non-binding, section 5.1): a control measure needs a proportionality test (suitable, necessary, balanced), information on its existence and purpose, no more data than strictly necessary and no other uses; it extends to "any other means of control" that processes personal data.
  - Whether NAS logs fall under art. 87 or art. 64.5(f) is for the DPO, HR or legal to say.
- **DPO [D/R].** Advises on all of this and on the impact assessment, and monitors compliance (Arts. 35(2), 39(1)). The repo holds no DPO, GDPR, LOPDGDD or staff-monitoring record (searched). The controller is the institute (its legal notice names "Asociación Centro de Investigación Cooperativa en Biomateriales"), not the Data Office [I]. A `gdpr@cicbiomagune.es` contact appeared in a search result but not on the legal-notice page I fetched, so confirm who the DPO is.
- **Retention limit [D/I].** I found no fixed period for such logs. The controller chooses and justifies it, tells staff, and enforces it: QuLog retention time plus maximum entries, and the same limit on exports and forwarded copies (exports on a backed-up share would persist in snapshots and the planned off-site backup). If the aim is only adoption statistics, counts without names avoid personal data.
