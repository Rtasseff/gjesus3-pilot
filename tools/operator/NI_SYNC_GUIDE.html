Your scans to gjesus3, in two commands

When your reconstructions are done, one command at the Molecubes Mac copies them to gjesus3, registers them and files them in your project. It only reads your scan folder. It never moves, renames or deletes anything there.

1 · See what's newni-ingest <your folder> --planLists new sessions in your corrections file. Copies nothing.
2 · Sync itni-ingest <your folder>Shows a table, asks Proceed? [y/N], then copies.
How it fits together

Where your data goes

Before you start

You need three things

  • To be at the Molecubes Mac, logged in as usual.
  • Your scans reconstructed. A reconstruction still running is simply picked up next time.
  • Your scan folder. In Finder: Documents ▸ volumes ▸ remiW11 ▸ data ▸ your name.
1

Open Terminal

Press ⌘ + Space, type Terminal, press Return. A white window with a text prompt opens. That's where you type the commands below.

2

See what's new

Type ni-ingest and a space. Then drag your folder from Finder into the Terminal window, which types its full path for you. Add a space and --plan, then press Return.

Terminal — bash
$ ni-ingest /Users/molecubes/Documents/volumes/remiW11/data/yourname --plan
INFO: live source (READ-ONLY): /Users/molecubes/Documents/volumes/remiW11/data/yourname
INFO: researcher: yourname   operator: yourname
INFO: corrections file: /Volumes/gnuclear/2026/Jesus/yourname/ni_corrections_yourname.csv
INFO: building preview (read-only)...
INFO: added 3 session row(s) to .../ni_corrections_yourname.csv. Open it, fix
      anything wrong / add extra_metadata (e.g. tracer=FDG), then re-run with --go.

It takes about a minute. The line corrections file: tells you exactly which file is yours. If it says nothing new to review, skip to step 4.

3

Check your corrections file

Open it in Excel on the Mac: in Finder, go to gnuclear ▸ 2026 ▸ Jesus ▸ your name. Each new session has one row, already filled in from your folder names. Change only what's wrong, then save and close.

session_pathprojectanimal_codesextra_metadata
1025/260522/1025_m110251tracer=FDG
1025/250529/1015_m10-15102510;15
1125/260709/1125_m411254tracer=FDG;dose=10 MBq

The highlighted cell is a real kind of mistake: the folder was typed 1015, but the animals belong to protocol 1025. Fixing it here files the scans in the right project. Your folder on the box stays as it is.

session_pathDon't change it. It's how the sync finds the session.
projectThe animal-protocol number (4 digits). Anything else becomes a project named Project-<what you typed>.
animal_codesThe mouse or rat numbers, separated by ;.
extra_metadataAnything else, as key=value. Most useful: the tracer, e.g. tracer=FDG.
You fix a session once. A reconstruction of the same scan that arrives weeks later gets your corrected values automatically. From a Windows PC the file is read-only, so edit it on the Mac.
4

Sync

Same command, without --plan. Check the table, type y and press Return.

Terminal — bash
$ ni-ingest /Users/molecubes/Documents/volumes/remiW11/data/yourname
INFO: corrections: 3 reviewed session(s) loaded
acq_id               sample_id     project     link name                         n_files
-------------------  ------------  ----------  --------------------------------  -------
ACQ-20260522-PET-001 1025_m1       PROJ-0015   PET_1025_m1_20260522_2026052...        2
ACQ-20260522-CT-001  1025_m1       PROJ-0015   CT_1025_m1_20260522_20260522...        3
ACQ-20260522-CT-002  1025_m1       PROJ-0015   CT_1025_m1_20260522_20260522...        3
3 new acquisition(s) to ingest; 0 already ingested (skipped)
INFO: 1 derived file(s) (CT attenuation maps) to copy into their project's outputs/derived/
Proceed? [y/N] y
  ...
INFO: ingest finished: 3 acquisition(s) ingested OK.
Leave the window open until it says ingest finished. A normal day's scans take a few minutes. The first sync of a folder holding months of scans can take half an hour.
In the project column, a value starting will auto-create: means that number has no project yet. If it's a typo, answer n, fix it in your corrections file, and run the sync again.
After the sync

What you'll find on gjesus3

Good to know

Run it as often as you like

Nothing is copied twice

The sync skips anything already on gjesus3, including scans that got there another way, for example from your copies on gnuclear.

Late reconstructions

A reconstruction you add later is picked up on your next sync and gets your corrections automatically.

Warnings you can ignore

Could not create hard link … queued, DB unreachable … pending-db, is_control is null, and lines starting [expand_batch] SKIP. The data office completes those parts later.

One sync at a time

Don't start a second sync while one is running, and don't close Terminal or log out until it says ingest finished.

If something goes wrong

What the messages mean

You seeWhat to do
command not found: ni-ingestClose Terminal and open a new window, then try again. If it still happens, contact the data office.
not a directoryThe path isn't a folder. Drag your own folder (the one with your name) from Finder into Terminal.
NAS root does not look validgjesus3 isn't connected right now. Nothing was written. Try again in a few minutes, then contact the data office.
Proceed? [y/N]The confirmation before copying. Type y and Return to go ahead, or just Return to stop.
A scan you expected isn't listedIt's most likely already on gjesus3, or its reconstruction hasn't finished. Run the sync again later.
Anything else, or an ERRORStop. Don't run it again and again. Copy the Terminal text and send it to the data office. A stopped sync is safe to leave.
